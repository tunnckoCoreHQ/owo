# Typed core with request types; the CLI builds from it

owo is two crates in one Cargo workspace. `owo-core` (`crates/core/`) is the library: one typed function per operation, one request type per operation, typed results and a typed error, the MCP server (`owo_core::mcp`) and the ACP proxy (`owo_core::acp`). `owo-cli` (`crates/cli/`) is the `owo` binary. The core has no clap and reads nothing from the process: no environment, no stdio, no exit. The caller passes the environment values in `Env` and the picked root, identity and project in `Select`. A program that links the core gets every operation as values, and the core tests use that API, the MCP server and the ACP proxy on in-memory streams, with no binary. With one package, clap was a dependency of the library, and a program that linked the library compiled it too.

Each request type reads itself (`Request::read`), and each read declares one field (`Request::fields` lists them): name, type, help text, default, allowed values and rules (a range, a field it conflicts with, a field it needs). Its defaults are in `Default`, and a limit is a core constant (`MAX_DAYS`). `operations()` lists every operation with its name words, its help line and its request type. The CLI builds its clap commands from that list, and the MCP server its tools and input schemas. Both give their arguments to the core as JSON values (`Args`), and the core maps them into the request (`Request::from_args`), opens the root, makes the typed call and returns a typed `Outcome`. A new option is added once, in the request type; the CLI flag and the MCP parameter follow from it.

The rules are declared once, on the fields. Each typed function checks its request against them (`Request::check`), so a request built by hand gets the same check as one built from arguments, and a broken rule is a usage error with a typed fault (`OutOfRange`, `Conflict`, `Needs`), never a crash. The CLI also gives the same declarations to clap, so a bad flag keeps clap's error and usage text.

An `owo_core::Error` has a kind (`Usage`, `Config`, `Io`, `Failed`), its text, and for the failures a caller may word itself, a typed `Fault`. The core text says what is wrong and names fields, never a flag, an environment variable, a command or an exit code. The CLI words a fault from its facts: a field as its flag, the `owo` command to run next, such as "run `owo add project`", and a usage error as clap words its own. The MCP server shows the core's plain text.

The MCP server is in the core, because its tools come from the request types and not from clap definitions. The `{ ok, data, warnings, errors }` envelope of an outcome is built in the core (`Outcome::envelope`), so a tool and a command with `--json` give the same JSON. The CLI renders the text for people, the `--json` output and the exit codes, and connects the process (arguments, environment, stdio, the agent process) to `mcp` and `acp`. The ACP proxy needs no rendering: it resolves the identity, lists the identities, reads the context text and stores the turns with core calls, on streams the caller gives it. The `owo acp` command only starts the agent process and hands the proxy its streams.

This supersedes [ADR-0004](0004-library-core-thin-adapters.md), where the library took a parsed clap command line, returned the rendered output and the exit code, and held the MCP server and the ACP proxy, which ran their calls as command lines.
