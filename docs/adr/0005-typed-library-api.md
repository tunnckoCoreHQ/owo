# Typed library API, CLI, MCP and ACP as consumers

The `owo` library (the root package, `src/`) is a typed API. A caller opens a root with `Root::open`, loads its identity with `Root::identity`, and calls one function per command on the `Root` or the `Identity`: `context`, `search`, `show`, `resolve`, `links`, `add`, `write`, `stamp`, `index`, `lint`, `state`, `review`, `soul_note`, `changes`, the exports, the session sync, and the free functions `slug`, `parse_turns` and `migrate_v1`. Each function takes typed arguments and returns a typed result or an `owo::Error`. The loaded identity carries the working project, so a call that uses it takes no project argument. The library has no clap, no rendered command output, no exit codes and no envelope, and it reads nothing from the process: the caller passes the environment values in `Env` and the picked root, identity and project in `Select`.

The library owns every default, limit and rule on arguments. A request type carries its defaults in `Default` (`ContextRequest`, `StateRequest`, `SearchRequest`, `ChangesRequest`, `CardRequest`, `SyncOptions`), a limit is a library constant (`MAX_DAYS`), and the library checks the rules (a number of days in range, `since` with `days`, `png` needs `out`) and returns a usage error. An `owo::Error` has a kind (`Usage`, `Config`, `Io`, `Failed`), its text, and for the failures a caller may word itself, a typed `Fault`. The library text says what is wrong and names no CLI command.

The CLI, the MCP server and the ACP proxy are consumers of that API, and none of them builds a command line for another or calls another. The CLI maps the clap arguments to the library requests. Its clap attributes repeat the library's defaults, limits and rules by referencing them, only so that its help and usage text stay as they are, and it words each fault in CLI terms, such as "run `owo add project`". The MCP server maps the JSON arguments of a tool call to the same library requests, with the library's defaults for the arguments it leaves out, and lets the library check the rules; its own error text covers only the shape of the arguments. It reads its tool list from the CLI's clap definitions. Both render a result with one set of functions, which build the text, the JSON envelope and the exit code, so a tool and a command give the same output.

The CLI and the MCP server are the `owo` binary in a second package, `owo-cli` (`cli/`), in the same Cargo workspace, because the rendering and the clap definitions are command-line concerns. With one package, clap was a dependency of the library, and a program that linked the library compiled it too.

The ACP proxy needs no rendering: it resolves the identity, lists the identities, reads the context text and stores the turns with library calls. So it stays in the library as `owo::acp`, on streams the caller gives it, and a program that links owo can run it. The `owo acp` command only starts the agent process and hands the proxy its streams.

A program that links the library gets the behavior of every command as values, and the library tests use that API, and the ACP proxy on in-memory streams, with no binary. A program that wants the MCP server runs `owo mcp`.

This supersedes [ADR-0004](0004-library-core-thin-adapters.md), where the library took a parsed clap command line, returned the rendered output and the exit code, and held the MCP server and the ACP proxy, which ran their calls as command lines.
