# A dry run keeps writes in memory

Each command that writes files takes `--dry-run`: it reports the files it would write, and writes none. Some commands read back what they wrote. The `new` command writes its template files, then loads the identity from disk to build the indexes and the state files. The `migrate` command runs `new`, reads `soul/state.json` and `identity.json` back, checks which targets exist, and at the end loads, indexes and stamps the identity. If a dry run only dropped the writes, these later steps would read files that are not there. They would fail, or give a result that is not the result of the real run.

So a dry run is one switch in the write layer, not a parameter of each command. The function `write::dry_run` runs a call with a list of kept targets, one list for each thread. While the list is there, `Writes::commit` adds its targets to the list and writes nothing. The reads that a command can make of its own writes go through `write::read`, `write::read_to_string` and `write::exists`, which look in the list first. Also, `Identity::load` adds the kept `.md` files under its folder to the files it walks. A dry run thus takes the same steps as the real run, on the same data, and gives the same result and the errors that come before the writes. At the end it returns each file and each missing folder the commits would write.

This has a cost. A new write must go through `Writes`, and a read of a file that the same call can write must go through the reads of `write`, or the dry run breaks. Three places write outside `Writes` and check `write::dry` instead: `new` makes no identity folder, the sync lock is not taken, and the cleanup of `new` and `migrate` after an error does not run.

The list belongs to one thread, so the calls of other threads write as usual. The ACP proxy stores turns on its own thread, so in a dry run it runs the whole loop of that thread inside one `write::dry_run`, and each store sees the turns of the earlier ones. The list goes away when the call returns or panics. The MCP server catches a panic and answers the next call on the same thread, and that call is not a dry run.

The other choice was a `dry_run` field on each of the fourteen request types, passed down to each commit. It would still need the reads that see the kept files for `new` and `migrate`, and it would add a parameter to each write path.
