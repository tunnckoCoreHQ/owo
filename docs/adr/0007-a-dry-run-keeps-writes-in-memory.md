# A dry run keeps writes in memory

Each command that writes files takes `--dry-run`: it reports the files it would write, and writes none. Some commands read back what they wrote. `new` writes its template files, then loads the identity from disk to build the indexes and the state files. `migrate` runs `new`, then reads `soul/state.json` and `identity.json` back, checks which targets exist, and at the end loads, indexes and stamps the identity. If a dry run only dropped the writes, these later steps would read files that are not there and fail, or report a different result than the real run.

A dry run is one switch for the write layer, not a parameter for each command. `write::dry_run` runs a call with a thread-local list of kept targets. While the list exists, `Writes::commit` adds its targets to it and writes nothing. The reads that a command can make of its own writes go through `write::read`, `write::read_to_string` and `write::exists`, which look in the list first, and `Identity::load` adds the kept `.md` files under its folder to the files it walks. So a dry run takes the same steps as the real run, on the same data, and returns the same result and the same errors. The list it returns names each file and folder once, in write order.

The cost: a write that does not go through `Writes`, and a read of a file the same call may have written that does not go through the `write` reads, breaks the dry run. Today three places write outside `Writes` and check `write::dry` instead: `new` makes no identity folder, the sync lock is not taken, and the cleanup of `new` and `migrate` after an error does not run. The switch is per thread, so the calls of other threads, such as the stores of the ACP proxy, write as usual. A guard ends the dry run also when the call panics, so the MCP server, which catches a panic and answers the next call on the same thread, does not keep it.

The alternative was a `dry_run` field on each of the fourteen request types, passed down to every `commit`. It would also need its own in-memory reads for `new` and `migrate`, so it would add the same reads, plus a parameter on every write path.
